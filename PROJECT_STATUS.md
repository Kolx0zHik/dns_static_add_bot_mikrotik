## Текущие цели

Первый рабочий этап проекта: Telegram-бот на Python 3.13 и aiogram 3 для безопасного
добавления DNS Static записей типа FWD на один или несколько MikroTik по SSH.

Ближайшая цель следующего этапа: усилить тестовое покрытие пользовательского сценария,
подготовить эксплуатацию и проверить работу с тестовым Telegram-ботом и MikroTik.

## Завершено

- Реализованы команды `/start` и `/add` с интерфейсом только на Inline Keyboard.
- Реализован выбор одного или нескольких MikroTik с разграничением доступа по Telegram ID.
- Поддержаны multi-router переменные `MIKROTIK_ROUTERS` и `MIKROTIK_<ID>_*`.
- Сохранена совместимость со старым форматом конфигурации одного роутера без
  `MIKROTIK_ROUTERS`.
- Пользователь видит только доступные ему роутеры; выбор пропускается при единственном
  доступном роутере.
- Сценарий `/add` принимает список доменов, по одному домену в строке.
- Выполняются нормализация, проверка DNS-имён, ограничение длины, проверка меток,
  запрет URL и специальных символов, а также проверка дубликатов в списке.
- Весь список подтверждается одной операцией; существующие DNS Static FWD записи
  пропускаются и отображаются отдельно в результате.
- Перед подтверждённой операцией повторно проверяются `router_id`, ACL пользователя и
  наличие соответствующего DNS-сервиса.
- RouterOS-команды централизованы, SSH-вызовы выполняются только сервисным слоем.
- Синхронный Paramiko-вызов запускается через `asyncio.to_thread`.
- Добавлена обработка текстовых и нетекстовых сообщений, отмены, устаревших callback и
  типовых ошибок без показа traceback пользователю.
- Добавлены unit-тесты конфигурации, `RouterCatalog`, клавиатур, валидатора доменов,
  фильтра контента, RouterOS-команд и пакетного DNS-сервиса.
- CI выполняет Black, Ruff и pytest, после чего собирает и публикует Docker-образ в GHCR.
- Версия Black закреплена на `26.5.1`, чтобы локальная проверка и CI использовали один
  форматтер.
- Production Compose использует `.env` из корня репозитория, как описано в README.

## Ключевые решения

- `RouterConfig` является неизменяемой `dataclass` и объединяет SSH-параметры и ACL
  одного роутера.
- `RouterCatalog` отделяет поиск роутера и вычисление доступных пользователю роутеров от
  Telegram- и SSH-слоёв.
- `Settings.allowed_users` строится как объединение ACL всех роутеров для глобального
  middleware; доступ к конкретному роутеру проверяется каталогом и handlers.
- `router_id` передаётся в callback data (`router:select:<id>`, `dns:add:start:<id>`) и
  сохраняется в FSM до подтверждения операции.
- Для каждого роутера создаются отдельные `SshClient` и `MikroTikDnsService`; логи
  содержат `router_id`.
- RouterOS-команды и экранирование аргументов сосредоточены в
  `app/services/routeros_commands.py`.
- `MemoryStorage` используется для FSM текущего этапа.

## Основные файлы

- `app/config.py` - загрузка и валидация legacy/multi-router конфигурации,
  `RouterCatalog`, проверка ACL, портов и SSH timeout.
- `app/models/router.py` - модель конфигурации роутера.
- `app/bot.py` - создание Dispatcher, middleware, каталога и DNS-сервисов.
- `app/handlers/dns.py` - Telegram-сценарий выбора роутера, ввода, подтверждения и
  выполнения DNS-операции.
- `app/keyboards/dns.py` - inline-клавиатуры и router-aware callback data.
- `app/validators/domain.py` - разбор и валидация списка доменов.
- `app/services/ssh.py` - централизованное SSH-взаимодействие.
- `app/services/mikrotik.py` - проверка и пакетное добавление DNS Static записей.
- `app/services/routeros_commands.py` - генерация RouterOS-команд.
- `tests/` - unit-тесты текущего функционала.
- `.github/workflows/docker-image.yml` - quality checks и Docker publish.
- `pyproject.toml` - зависимости и настройки Black, Ruff и pytest.
- `.env.example`, `README.md`, `requirements.md`, `AGENTS.md` - конфигурация, запуск и
  требования проекта.

## Известные проблемы и риски

- Нет отдельных handler/FSM-тестов на aiogram updates для одного и нескольких роутеров,
  подмены `router_id`, повторного callback, отмены и выбора правильного DNS-сервиса.
- `MemoryStorage` теряет незавершённые FSM-сценарии при перезапуске и не подходит для
  горизонтального масштабирования без отдельного хранилища.
- `SshClient` использует `paramiko.AutoAddPolicy`, поэтому host key принимается
  автоматически. Перед production нужно выбрать и реализовать явную политику доверия к
  host key и задокументировать её конфигурацию.
- Не выполнен smoke-тест в тестовом Telegram-боте и на тестовом MikroTik.
- Docker Compose локально не проверен из-за отсутствия Docker CLI.
- GitHub Actions выдаёт предупреждение о legacy Node.js 20 в `actions/checkout@v4` и
  `actions/setup-python@v5`; текущий workflow при этом завершается успешно.

## Опробованные, но не сработавшие подходы

- Multi-router commit `b39175e` остановился в CI на Ruff, поэтому тесты и Docker build
  тогда не запускались.
- После удаления шага Ruff commit `c149c82` остановился на pytest из-за отсутствующего
  импорта `START_ADD_DNS_CALLBACK` в `tests/test_dns_keyboards.py`.
- Первые форматирующие коммиты `0c13159` и `8357a82` не устранили расхождение CI:
  зависимость `black>=24.10` разрешала установку Black `26.5.1`, который иначе
  форматировал пустую строку в `tests/test_dns_keyboards.py`.
- Попытка заменить установленный APT-пакет Black через системный `pip` не сработала из-за
  отсутствия `RECORD` у Debian-пакета; для проверки использовались отдельные virtualenv.
